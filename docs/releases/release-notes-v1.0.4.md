## qimgv v1.0.4 — 中文支持修复 + 性能优化

本版本修复了多个中文环境下的显示与稳定性问题，并解决了打开图片时的性能回退。

### 修复内容

**1. 按 i 打开 EXIF 信息面板崩溃（0xc0000005）**
构造函数中 `setPosition()` 会立即触发 `recalculateGeometry()`，但它在 XMP 控件创建**之前**执行，而相关成员指针未初始化 → 解引用野指针导致崩溃。现已调整初始化顺序、成员默认初始化，并对整个路径加空指针防护。

**2. 中文路径下的文件无法打开（提示"没有文件打开"）**
目录枚举使用 `std::filesystem::path::generic_string()`（Windows 上按 GBK 编码）再用 `QString::fromStdString`（按 UTF-8 解码），导致中文目录/文件名全部乱码，列表中的路径与实际路径不符。现已全面改用宽字符 `generic_wstring()` + `fromStdWString()`（8 处），隐藏文件判断改用 `GetFileAttributesW`。

**3. EXIF 时间与经纬度格式未生效**
格式化正则写的是 `\d`，但 GCC 会把 C++ 字符串字面量中的未知转义 `\d` 吞成字面 `d`，正则实际变成 `^(d{4}):(d{2})...` 永不匹配。现已双写转义，时间显示为 `2023-03-08 20:52:18`，经纬度显示为 `23°14'30.80"`。

**4. EXIF 文本乱码 / 格式不一**
- EXIF 的 ASCII/Undefined 字段**不保证是 UTF-8**（可能是 GBK 或纯二进制）。原先统一按 UTF-8 解码会输出乱码。现改为：先按 UTF-8 解码，若出现替换字符则回退本地代码页（`fromLocal8Bit`）。
- 大型二进制字段（如微信 `UserComment`，实测 23,840 字节）不再倾倒几 KB 乱码，改为显示 `(二进制数据 N 字节)`。
- 非中文界面下，EXIF/XMP 标签名保留 exiv2 原始英文名（原先无论语言都显示硬编码中文）；XMP 折叠标题改用 `tr()` 并在 zh_CN 中保留「XMP 信息」。

**5. 打开图片变慢 / 切换图片卡顿**
`guiSetImage()` 原先在**每次加载图片**时都完整解析一遍 EXIF+XMP，即使从不查看信息面板。现改为**惰性拉取**：只有信息面板实际显示时才解析，面板已打开时切换图片会自动刷新。实测连续切图最坏耗时由 297ms 降至 223ms（抖动明显减小），启动时间与集成 exiv2 之前的版本持平。

**6. 拖动 EXIF 面板会改变整个应用窗口大小**
`QSizeGrip` 默认调整其顶层窗口尺寸，而面板是 viewer 的子控件。现改为自定义 `PanelSizeGrip`，只调整面板自身并遵守最小尺寸。

**7. 元数据读取加固**
对损坏/异常文件增加防御：`assert` 改为检查返回值，补充 `catch(...)` 兜底，避免读取失败导致信息栏卡在"没有文件打开"。

### 安装说明

- **`qimgv-x64_v1.0.4.exe`** — 安装版（NSIS）。若安装时提示文件被占用，请先关闭所有 qimgv 窗口或重启后重试。
- **`qimgv-x64_v1.0.4.7z`** — 便携版，解压即用。

### 已知说明

- EXIF 标签的中文翻译为内置词典，仅在中文界面下启用；其他语言环境显示英文原始标签名。
- 读取 EXIF 需要 `libexiv2.dll`（已随包附带）。
